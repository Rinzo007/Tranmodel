# AequilibraE + TNDP backend

`Tranmodel` использует AequilibraE как расчётное ядро, а `src/tndp/` — как решатель задачи проектирования маршрутной сети по матрице корреспонденций.

## Архитектура

`OSM PBF → OSM layers → WorldPop/POI → транспортные зоны → zone OD → OD-коридоры → кандидаты маршрутов → TNDP → AequilibraE Transit Assignment → local search`

Здесь принципиально разделены три сущности:

- **транспортная зона** — единица формирования спроса и строк/столбцов OD-матрицы;
- **остановка ОТ** — физическая точка посадки/высадки;
- **дорожный узел** — вершина реального графа улиц.

Одна сущность больше не используется как суррогат другой.

## Транспортные зоны

`src/zones.py` создаёт полигоны зон регулярной сеткой, обрезанной границей Воронежа. По умолчанию размер зоны — 750 м. Население и притяжение агрегируются из WorldPop/POI-подготовки, а центроид зоны привязывается к ближайшим дорожным узлам.

Результаты:

- `data/cache/zones/zones.parquet` — полигоны зон, ID, центроиды, население и притяжение;
- `data/cache/zones/zones_report.json` — статистика зон;
- `data/report/zones_report.md` — отчёт.

AequilibraE также использует центроиды зон и коннекторы для доступа к сети; остановки ОТ остаются отдельными объектами. citeturn640558search1turn640558search14

## OD-модель

`src/zone_od.py` строит OD-матрицу уже **между транспортными зонами**. Стоимость между зонами рассчитывается по реальному дорожному графу, а не по расстоянию между остановками.

Результаты:

- `data/cache/zone_od/od_matrix.parquet` — квадратная OD-матрица с `zone_id` в индексах и столбцах;
- `data/cache/zone_od/od_pairs.parquet` — разреженное представление OD;
- `data/cache/zone_od/zone_travel_time_min.npy` — время между зонами;
- `data/cache/zone_od/zone_od_report.json` — статистика.

## Реальный дорожный граф

`src/tndp/network.py` строит граф непосредственно из геометрии OSM-дорог. Вес ребра — расчётное время движения, длина хранится отдельно. Остановки привязываются к вершинам графа, после чего компактный граф остановок получает стоимость через реальные кратчайшие пути по улицам.

Для экспорта маршрутов `src/tndp/export.py` также восстанавливает геометрию по кратчайшему пути реального дорожного графа, а не рисует прямые хорды между остановками.

## Синтез маршрутов

`src/tndp/` оптимизирует целые маршруты, а не выбирает следующую остановку локальным greedy-правилом.

1. Зоны и OD формируют сильнейшие коридоры спроса.
2. Концы коридоров переводятся в ближайшие доступные остановки.
3. `candidates.py` строит допустимые варианты по графу дорог.
4. Терминальность ограничивается `is_terminal` из `voronezh_routes_terminals.geojson`.
5. Слабые кандидаты отсеиваются быстрым оценщиком.
6. Лучшие варианты проверяются через `AequilibraE TransitAssignment` / `Optimal Strategies`.
7. `optimizer.py` выполняет добавление маршрутов и локальное улучшение.
8. `mutations.py` выполняет `remove`, `extend`, `shorten`, `replace`.
9. `frequency.py` рассчитывает требуемую частоту по нагрузке и вместимости.

AequilibraE поддерживает отдельные зоны/центроиды и соединяет их с остановками через connector links, что соответствует этой архитектуре. citeturn640558search0turn640558search1

## Запуск

После подготовки OSM/WorldPop:

```powershell
pip install -r requirements.txt
python -m src.zone_od
python -m src.tndp.cli --min-routes 10 --max-routes 30 --corridors 300 --candidates-per-corridor 8
```

`run_tndp()` автоматически построит zone OD, если кэш отсутствует.

Быстрый режим без полного назначения:

```powershell
python -m src.tndp.cli --surrogate-only
```

Через Streamlit:

```powershell
streamlit run app.py
```

## Результаты

- `data/cache/tndp/generated_routes.json` — сгенерированные маршруты;
- `data/cache/tndp/generated_routes.geojson` — маршруты вдоль реальной дорожной сети;
- `data/cache/tndp/history.json` — история поиска;
- `data/cache/tndp/evaluation_cache/` — кэш AequilibraE;
- `data/cache/tndp/tndp_report.json` — машинный отчёт;
- `data/report/tndp_report.md` — отчёт.

## Benchmark

`src/tndp/benchmark.py` содержит адаптер формата `RenatoArbex/TransitNetworkDesign` для стандартных сетей Mandl/Ceder/Mumford/Rivera.

## Ограничения текущей версии

Генерация зон уже отделена от остановок, но пока используется регулярная сетка. Для финальной модели Воронежа можно перейти к более содержательному зонированию: дорожные кварталы/микрорайоны/гексагоны с адаптивным размером по плотности населения. Эксплуатационные параметры ОТ также пока являются модельными и требуют реальных частот, расписаний, вместимости и времени движения.
