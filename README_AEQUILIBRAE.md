# AequilibraE + TNDP backend

Ветка `aequilibrae-migration` использует AequilibraE как расчётное ядро транспортной модели, а собственный модуль TNDP — для синтеза маршрутной сети по матрице корреспонденций.

## Основной контур

`OSM PBF → OSM layers → WorldPop/POI → транспортные зоны → OD matrix → OD-коридоры → кандидаты маршрутов → TNDP → AequilibraE Transit Assignment → оценка → улучшение сети`

## TNDP

Модуль `src/tndp/` является оптимизатором маршрутной сети. Он не использует старый stop-by-stop greedy из `phase3.py`.

Пайплайн:

1. `phase2` формирует матрицу OD.
2. Из наиболее сильных OD-пар формируются пространственные коридоры.
3. `candidates.py` строит несколько допустимых маршрутов по дорожной сети.
4. Учитываются ограничения терминальных остановок из `voronezh_routes_terminals.geojson`.
5. Кандидаты предварительно фильтруются быстрым суррогатным критерием.
6. Лучшие кандидаты оцениваются настоящим `AequilibraE TransitAssignment` с алгоритмом `Optimal Strategies`.
7. `optimizer.py` добавляет целые маршруты в сеть только при улучшении целевой функции, затем выполняет локальную замену маршрутов.
8. Для ускорения результаты AequilibraE кэшируются по хешу набора маршрутов.

Полный оценщик находится в `src/tndp/aequilibrae_eval.py`.

## Целевая функция

Оценка учитывает:

- пользовательскую обобщённую стоимость поездки;
- время ожидания;
- время в транспортном средстве;
- пешеходное время;
- пересадки и штраф за пересадку;
- необслуженный спрос;
- эксплуатационную длину маршрутной сети.

## Исходная маршрутная сеть

`voronezh_routes_terminals.geojson` хранится непосредственно в репозитории. Он содержит координаты остановок, `routes`, `is_terminal` и `route_count`.

Этот файл используется как источник остановок и терминальных ограничений для синтеза. Он также остаётся эталоном существующей маршрутной сети для последующего сравнения с сгенерированной.

## AequilibraE Public Transport

Для каждого набора кандидатных маршрутов TNDP создаётся временный GTFS и импортируется в копию проекта AequilibraE. Это сделано потому, что AequilibraE 1.7.0 предоставляет импорт GTFS и построение `TransitGraph`, но пока не предоставляет программного добавления маршрутов напрямую в route system.

AequilibraE затем выполняет:

`GTFS → TransitGraph → TransitAssignment → Optimal Strategies`

Для тестового GTFS используются явные модельные допущения: частота маршрута задаётся полем `Route.frequency_vph`, скорость движения и время стоянки задаются параметрами оценщика.

## Запуск

После подготовки OSM/WorldPop слоёв и Фазы 2:

```powershell
pip install -r requirements.txt
python -m src.tndp.cli --min-routes 10 --max-routes 30 --corridors 300 --candidates-per-corridor 8
```

Быстрый режим без назначения AequilibraE:

```powershell
python -m src.tndp.cli --surrogate-only
```

Через Streamlit:

```powershell
streamlit run app.py
```

Раздел **TNDP — Синтез маршрутов** запускает генерацию сети. По умолчанию включено полное назначение AequilibraE.

## Результаты

- `data/cache/tndp/generated_routes.json` — итоговый набор маршрутов;
- `data/cache/tndp/history.json` — история улучшений;
- `data/cache/tndp/evaluation_cache/` — кэш результатов AequilibraE;
- `data/cache/tndp/tndp_report.json` — машинный отчёт;
- `data/report/tndp_report.md` — человекочитаемый отчёт.

Также сохраняются GTFS и результаты назначения в каталоге AequilibraE при отдельном полном запуске.

## Benchmark

`src/tndp/benchmark.py` предназначен для проверки решателя на сетях из `RenatoArbex/TransitNetworkDesign` (Mandl, Ceder, Mumford, Rivera). Репозиторий предоставляет стандартные `nodes`, `links`, `demand`, ограничения терминальных узлов и наборы опубликованных решений, что позволяет сравнивать качество нового алгоритма с литературными решениями.

## Важное ограничение

Это первая полноценная версия связки TNDP + AequilibraE. Основной оставшийся этап — калибровка параметров по реальным частотам/расписанию и пассажиропотокам, а также более сильный поиск маршрутов (например, обмены/удаления/расширения и затем метаэвристика) после проверки базового решателя на benchmark-сетях.
