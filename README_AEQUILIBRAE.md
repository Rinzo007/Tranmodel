# AequilibraE + TNDP backend

Ветка `aequilibrae-migration` использует AequilibraE как расчётное ядро, а `src/tndp/` — как решатель задачи проектирования маршрутной сети по матрице корреспонденций.

## Основной контур

`OSM PBF → OSM layers → WorldPop/POI → спрос → OD matrix → OD-коридоры → кандидаты маршрутов → TNDP optimizer → AequilibraE Transit Assignment → оценка → local search`

## Синтез маршрутов

`src/tndp/` полностью заменяет старый stop-by-stop генератор. Оптимизируются целые маршруты.

1. `phase2` подготавливает OD-матрицу.
2. Из сильнейших OD-пар формируются пространственные коридоры.
3. `candidates.py` строит варианты маршрутов по дорожному графу.
4. Учитываются терминальные ограничения из `voronezh_routes_terminals.geojson`.
5. Кандидаты проходят быстрый предварительный отбор.
6. Для выбранных наборов выполняется `AequilibraE TransitAssignment` / `Optimal Strategies`.
7. `optimizer.py` выполняет конструктивное добавление маршрутов.
8. `mutations.py` выполняет локальные операции `remove`, `extend`, `shorten`, `replace`.
9. `frequency.py` содержит расчёт требуемой частоты по пиковой нагрузке и вместимости.
10. Результаты полного назначения кэшируются по хешу маршрутного набора.

## Целевая функция

Учитываются:

- обобщённая пользовательская стоимость;
- время в транспортном средстве;
- ожидание;
- пешее время;
- пересадки и штраф пересадки;
- необслуженный спрос;
- эксплуатационная длина сети.

## Исходная маршрутная сеть

`voronezh_routes_terminals.geojson` хранится в репозитории. Он содержит координаты остановок, `routes`, `is_terminal` и `route_count`.

Файл используется для построения множества допустимых остановок и терминальных ограничений. Сама существующая сеть не копируется в результат: TNDP генерирует новую сеть на основе OD-спроса.

## AequilibraE

Каждый оцениваемый набор маршрутов преобразуется во временный GTFS и импортируется в копию проекта AequilibraE. Затем строится `TransitGraph` и выполняется назначение методом `Optimal Strategies`.

Модельные параметры GTFS заданы явно: частота берётся из `Route.frequency_vph`, а скорость и время стоянки являются параметрами оценщика. Их необходимо заменить реальными данными для окончательной калибровки.

## Запуск

После подготовки OSM/WorldPop слоёв и OD-матрицы:

```powershell
pip install -r requirements.txt
python -m src.tndp.cli --min-routes 10 --max-routes 30 --corridors 300 --candidates-per-corridor 8
```

Быстрый режим:

```powershell
python -m src.tndp.cli --surrogate-only
```

Через Streamlit:

```powershell
streamlit run app.py
```

## Результаты

- `data/cache/tndp/generated_routes.json` — сгенерированные маршруты;
- `data/cache/tndp/history.json` — история поиска;
- `data/cache/tndp/evaluation_cache/` — кэш оценки;
- `data/cache/tndp/tndp_report.json` — машинный отчёт;
- `data/report/tndp_report.md` — отчёт.

## Benchmark

`src/tndp/benchmark.py` содержит адаптер формата `RenatoArbex/TransitNetworkDesign` для Mandl, Ceder, Mumford и Rivera. Это позволяет проверять алгоритм на стандартных сетях и сравнивать с опубликованными наборами маршрутов.

## Следующий этап

Для производственной модели Воронежа нужны: реальные частоты/расписания, более точные транспортные зоны вместо модели «остановка = зона», калибровка по наблюдаемым пассажиропотокам и затем более сильная метаэвристика поверх уже работающего конструктивного + локального поиска.
